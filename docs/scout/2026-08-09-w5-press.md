## C. The headline fallback

### C6 — there is no headline "fallback"; there is one blunt truncator

The only truncation in the flavor path is `StaticPoolProvider.Cap`, at
`src/Agora.Mod/Llm/StaticPoolProvider.cs:426-430`:

```csharp
private static string Cap(string text, int maxLength)
{
    if (string.IsNullOrEmpty(text)) return string.Empty;
    return text.Length <= maxLength ? text : text.Substring(0, maxLength).TrimEnd();
}
```

**Confirmed: it can cut mid-word.** It is a raw `Substring` with a trailing-whitespace trim; there
is no word-boundary search, no ellipsis, no fallback template. Contrast with
`FlavorPromptBuilder.TruncateSituation` (line 99), which *does* back up to a line boundary — the
prompt builder is careful here and the pool is not.

The place a **district name** gets cut mid-word is `SafeName`, StaticPoolProvider.cs:411-416:

```csharp
private static string SafeName(DistrictSnapshot district)
{
    string name = district.Name;
    if (string.IsNullOrEmpty(name)) name = district.Id;
    return Cap(name, 60);
}
```

A player district named longer than 60 characters is chopped at character 60, mid-word, *before*
substitution. The composed headline is then `Cap(..., 90)`'d a second time, which can chop the
template's own trailing words (e.g. `"{district} says it has been waiting long enough"` with a
60-char name is 97 chars → cut to 90, losing `"nough"`).

**Placeholder syntax: `{mood}` and `{district}`** — single braces, plain `string.Replace`, no regex,
no escaping. Substitution happens in exactly one place, `UniqueLine`
(StaticPoolProvider.cs:379-392):

```csharp
if (!string.IsNullOrEmpty(placeholder)) line = line.Replace(placeholder, value);
```

There is **no "placeholder cannot be substituted" branch**. If `value` were null, .NET treats it as
empty and the token simply vanishes, leaving a headline beginning with a space. That path is
currently unreachable — `SortedDistricts` (line 394) drops districts with an empty `Id`, and
`SafeName` falls back to `Id` — but nothing asserts it, and any new template family would inherit
the same silent behaviour.

`FlavorCacheMigration` deliberately **prunes rather than truncates** over-long cached articles
(see its class comment, lines 31-36) — a different and better policy than `Cap`'s.

### E11 — argument construction, and the nested-quoting hazard

`src/Agora.Mod/Llm/ClaudeCliRunner.cs:101`:

```csharp
public const string Arguments = "-p --output-format json";
```

`BuildStartInfo`, lines 241-263 — both branches:

```csharp
if (ClaudeCliLocator.NeedsCommandShell(executablePath))
{
    // cmd /d /s /c "" <path> " args" - the outer quotes are cmd's documented way of
    // handling a quoted program path, and /d skips AutoRun scripts that could otherwise
    // print junk onto our stdout.
    startInfo = new ProcessStartInfo
    {
        FileName = "cmd.exe",
        Arguments = "/d /s /c \"\"" + executablePath + "\" " + Arguments + "\""
    };
}
else
{
    startInfo = new ProcessStartInfo
    {
        FileName = executablePath,
        Arguments = Arguments
    };
}
```

The `cmd.exe` branch is the **normal Windows case**, not an edge case:
`ClaudeCliLocator.ExecutableNames` (line 37) is `{ "claude.cmd", "claude.exe", "claude.bat",
"claude" }` with `.cmd` **first**, because `npm i -g` installs a `.cmd` shim, and `CreateProcess`
under `UseShellExecute = false` cannot execute a `.cmd` (`NeedsCommandShell`, line 127).

**Where `--model <model>` goes.** Because both branches interpolate the same `Arguments` constant,
appending to that constant reaches both:

- **Direct branch:** `Arguments` is passed verbatim → `-p --output-format json --model X` works.
- **cmd.exe branch:** the produced string becomes
  `/d /s /c ""C:\Users\u\AppData\Roaming\npm\claude.cmd" -p --output-format json --model X"`.
  Also works — **as long as the appended text contains no double quote.**

**The hazard is quoting, and it is real.** The whole tail after `/c` is wrapped in one pair of outer
quotes. `cmd /s /c` has a documented special rule: with `/s`, it strips the *first* and *last*
quote character of the command string and passes everything between them through untouched. So:

1. Any `"` inside the model value breaks the pairing and cmd re-parses the line, typically silently
   running the wrong thing or nothing. `"--model \"" + model + "\""` compiles and looks careful, and
   is exactly the construction that breaks here.
2. `&`, `|`, `^`, `<`, `>`, `%` in a model string would be interpreted by cmd. `%FOO%` would be
   expanded.
3. The direct branch has none of these problems, so a bug introduced here would be invisible on any
   machine where the CLI resolved to `claude.exe` and would only bite `.cmd` users — i.e. most
   Windows players, and quite possibly not the developer.

Safe shape: keep the value bare (`" --model " + model`) and **validate the model id against a
conservative character class** (`[A-Za-z0-9._-]`) before it ever reaches either branch, rejecting
anything else back to the default. That check belongs next to the env read, not in the runner.

### F13 — `useSimulationHeldPaused`

`ui/src/shell/pause.ts`, the whole file is 55 lines; the hook is lines 24-55:

```ts
export function useSimulationHeldPaused(active: boolean): void {
  useEffect(
    function () {
      if (!active) {
        return undefined;
      }

      let subscription: { dispose(): void } | null = null;
      try {
        // The listener is required by the binding and is of no interest to us: the pause is the
        // subscription itself, not anything the barrier reports back.
        subscription = time.simulationPausedBarrier$.subscribe(function () {
          /* the subscription is the effect */
        });
      } catch (error) {
        console.warn("[AGORA] could not take the simulation pause barrier", error);
        return undefined;
      }

      return function () {
        try {
          if (subscription !== null) {
            subscription.dispose();
          }
        } catch (error) {
          console.warn("[AGORA] could not release the simulation pause barrier", error);
        }
      };
    },
    [active],
  );
}
```

Signature: `(active: boolean) => void`. Import is `import { time } from "cs2/bindings"` (line 2).

Semantics, all confirmed from the code:

- **Refcounted over `time.simulationPausedBarrier$`** — yes. The *subscription itself* is the pause;
  the listener body is empty. Per the file's own doc comment (lines 7-9), `TimeUISystem` forces speed
  to zero while at least one observer is subscribed and restores the player's prior speed when the
  count reaches zero. (That claim is about game code and I did **not** verify it against the shipped
  assemblies — see open question Q3.)
- **On unmount:** the effect's cleanup runs, `subscription.dispose()` releases the barrier, the game
  restores the speed. Nothing is captured or restored by our code.
- **When `active` flips:** `[active]` is the dep array, so React tears down and re-runs the effect.
  `true → false` runs the cleanup (un-pause) and the new effect returns `undefined` immediately.
  `false → true` takes a fresh subscription. There is no stale-subscription path.
- **Failure:** a throw from `subscribe` (no `TimeUISystem` outside a loaded game) is caught, warned,
  and the hook returns `undefined` — no pause taken, no error propagated.

The file explicitly rejects `SimulationSystem.selectedSpeed = 0` (lines 12-19) with two named
reasons: the setter is a no-op while loading and the game re-applies its own speed afterwards, and
manual capture/restore turns un-pausing into a bug that must be handled on unmount, save load, quit
to menu and boundary catch. **`fixplan.md:305-308` proposes exactly the approach this file was
written to replace.** That bullet is obsolete and would be a regression if implemented.
