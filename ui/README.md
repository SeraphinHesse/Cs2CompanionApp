# ui/ — bootstrap steps

This folder holds the dashboard's **source** (`src/`, `mod.json`). It does **not** yet hold a
build: `package.json`, `tsconfig.json` and the webpack config are generated by the CS2 UI template,
and that template needs the modding toolchain installed, which it is not yet.

Writing those files by hand would be guesswork — the `cs2/api`, `cs2/ui`, `cs2/bindings` and
`cs2/modding` packages resolve out of the toolchain's own location, not from the public npm
registry, so an invented `package.json` would not install.

## Once the toolchain is installed

1. From this folder, generate the template into a scratch directory:

   ```
   npx create-csii-ui-mod
   ```

2. Copy the generated `package.json`, `tsconfig.json` and webpack/build config into `ui/`.

3. **Keep this repo's `mod.json` and `src/`.** Reconcile only one field: `id` must equal
   `Agora.Mod`'s assembly name (`Agora.Mod`), which is what links the UI mod to the code mod.

4. Install and build:

   ```
   npm install
   npm run build
   ```

5. Wire the UI build into the C# build by adding this to `src/Agora.Mod/Agora.Mod.csproj`:

   ```xml
   <Target Name="BuildUI" AfterTargets="AfterBuild" Condition="Exists('$(MSBuildProjectDirectory)\..\..\ui\node_modules')">
     <Exec Command="npm run build" WorkingDirectory="$(MSBuildProjectDirectory)\..\..\ui" />
   </Target>
   ```

   The `Condition` matters: without it, anyone who has not run `npm install` gets a broken C# build.

## Node version

The templates target **Node 20.11**. This machine has Node 24. If webpack misbehaves, pin with nvm
rather than debugging the toolchain's build — the version gap is the likely cause, not your config.

## Verifying

Launch the game with `--uiDeveloperMode` and open `http://localhost:9444/` for the UI debugger.
`npm run dev` gives hot reload against the running game.
